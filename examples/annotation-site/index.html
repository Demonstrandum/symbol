The useful life of a small tool

Software becomes durable when its ordinary path stays obvious and its advanced machinery remains available without becoming mandatory.

A small tool earns trust through proportion. The first action should be visible, reversible, and unsurprising. Features can accumulate, but each one should preserve the shape of the simple case rather than forcing every user to understand the most complicated one.

Names matter because they become the handles people remember. A good interface uses familiar nouns for stable things and precise verbs for change. It should be possible to guess a command, read its help, and recover from a mistake without learning the implementation beneath it.

Storage systems have a second obligation: uncertainty must bias toward preservation. Metadata can be rebuilt and indexes can be compacted, but user bytes should move to quarantine before any process is allowed to call them disposable.

A typed protocol helps only when the types survive contact with the wire. Structured versions should be parsed as versions, hashes should be validated as hashes, and malformed responses should fail loudly instead of becoming plausible empty objects.

The result is not minimal software. It is software with a clear centre: easy to begin, transparent when examined, and conservative with anything that cannot be recreated.
